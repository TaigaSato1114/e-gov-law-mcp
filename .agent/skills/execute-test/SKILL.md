# テスト実行規約

## 目的
実装完了後、追加・修正した機能が正しく動作しているか、および既存機能に悪影響（デグレード）を与えていないかを、`pytest` を用いて最小限のコストで確実に検証する。

## テスト実行の基準（範囲）

- **全件実行は不要**: ワークスペース全体のすべてのテストを毎回実行する必要はありません。
- **影響範囲の絞り込み**: 関連する `[設計書]○○.md` の「5. 影響範囲」に挙げられたファイル、および今回直接修正・追加したファイルに関連するテストコード（`tests/` ディレクトリ内など）に限定して実行してください。
- **合格基準**: **影響範囲として特定したテストケースがすべて「Pass」すること。**

---

## 課される振る舞い・ワークフロー（サブスキルとしての動き）

AIエージェントは、実装フェーズの完了後、または本Skillsがトリガーされた際、以下のステップを厳守して行動してください。

### 1. テスト対象の特定（設計書との連動）
作成済みの `./plan/[設計書]○○.md` を読み込み、「5. 影響範囲」および「4. 作業手順」を確認してください。今回の修正によって影響を受ける既存のテストファイル、または新設すべきテストケースを特定します。

### 2. テストの実行（pytestの呼び出し）
特定したテストファイル、または特定のテスト関数に的を絞って `pytest` を実行してください。
> **実行例**: 
> - ファイル指定: `pytest tests/test_affected_feature.py`
> - 特定のテストのみ: `pytest tests/test_affected_feature.py -k "test_specific_behavior"`

### 3. エラー時の自己修復
テストが失敗（Fail）した場合、エラーログを分析し、原因が「実装コードのバグ」か「テストコード側の不整合」かを判断してください。コードを修正し、**対象のテストがすべてPassするまで**ステップ2〜3を繰り返してください。

### 4. ユーザーへの実行結果報告
テストがすべてPassしたら、チャットメッセージにてユーザーに以下の内容を簡潔に報告してください。
1. **実行したテストファイル・ケース名**
2. **テスト結果（Passの成否、実行件数）**
3. **（必要に応じて）テスト実行時の主要なログのサマリー**

## 依存関係・前提条件（Skills間の連携ルール）
- 本Skillは、原則として `design-plan` Skillによって `./plan/[設計書]○○.md` が作成され、実装が完了した状態のワークスペースに対して実行されます。
- 設計書が存在しない場合は、Gitの差分（`git diff`）から影響範囲を自身で自律的に推測して実行してください。
