# 機能実装規約

## 目的
`design-plan` Skillで確定した設計・計画書に基づき、正確かつクリーンにソースコードを実装・修正する。また、実装後は自律的にテストスキルとコミットスキルを呼び出し、品質の保証と変更の記録までをワンストップで完了させる。

## 前提条件
- `./plan/[設計書]○○.md` が存在し、Gitにコミット済み（計画が確定している状態）であること。

---

## 課される振る舞い・ワークフロー（Skillsパイプライン）

AIエージェントは、本Skillsが呼び出された際、以下のステップを厳守して行動してください。

### 1. 設計書の読み込みとコード実装
確定した `./plan/[設計書]○○.md` の「3. 実装方針・アプローチ」および「4. 作業手順」を厳密に確認し、対象となるソースコードの修正・追加を行ってください。
> **注意**: 新規機能の実装に伴い、新しいテストコード（`test_○○.py` など）の作成が必要な場合は、この段階で実装コードと合わせてテストコードも記述してください。

### 2. テストスキルの呼び出し（Skill連携①）
コードの実装（およびテストコードの記述）がすべて完了したら、ユーザーに確認を挟むことなく、**即座に `execute-test` Skillを呼び出して**テストを実行してください。
- **不合格時の振る舞い**: テストが1件でも失敗（Fail）した場合は、`execute-test` スキルの規約（自己修復）に従い、**すべてのテストがPassするまで**コードの修正とテスト実行を繰り返してください。

### 3. コミットスキルの呼び出し（Skill連携②）
`execute-test` スキルにより、影響範囲のテストが**すべて正常にパス（Pass）したことを確認したら、即座に `commit` Skillを呼び出して**、変更したソースコード群をGitにコミットしてください。
- **コミット時の注意**: `commit` 規約に基づき、今回の修正内容に最も合致するType（`feat`, `fix`, `refactor`, `test` など）およびScopeを正しく選択すること。

### 4. パイプライン完了報告
コミットが正常に完了したことを確認した後、チャットメッセージにてユーザーに以下の内容を報告し、タスクを完了してください。
1. **実装・修正した主なファイルの一覧**
2. **テストがすべてPassしたことの報告**
3. **コミットメッセージ（`commit` スキルで生成したもの）**
